# <11/21–11/23 更新日誌>

## BIO 自動化與 Slimefun Parser

- 完善 Vanilla BIO 增量更新，新增 `refresh-batch`，支援 Tag／Group 補產、指定 Preview 更新與批次重新命名。寫入前預設試跑及備份，避免重建批次時覆蓋人工內容。既有 53 份預覽已確認來源，實際更新待驗證。
- 統一材料集合回退規則，單一成員直接連結材料，多成員使用擇一材料；保留數量與 `obsf:choices` 相容性。**材料判斷應依實際候選，而非持續擴充特殊案例白名單。**
- 強化 SCAN → PUBLISH → ARCHIVE，加入設備遞迴依賴、循環診斷、來源變更重掃、SHA-256 封存驗證與 Git 復原機制。ZIP 驗證改用 .NET SHA256，避免 PowerShell 子程序找不到 `Get-FileHash`。部分封存及復原實測仍待完成。
- 統一 Parser／Generator 架構，新增 Normalized JSON adapter 與共用 `ob-cli`，Slimefun、Vanilla 共用 Review、Preview 與發布流程。**不再為不同插件建立獨立 Generator 或發布器，避免維護多套相似系統。**
- Slimefun Parser V1.1 加入 Constructor 簽名與委派追蹤，可解析 ID 的註冊呼叫由 126 增至 412／547。初版因 `preRegister` 判定過寬遺失 35 條配方，修正後全部恢復；341 項回歸測試通過。**事件註冊不等於配方變更，應先確認實際影響再排除解析結果。**
- 固定來源解析取得 **137 條可審核配方與 286 則診斷**。BATTERY、CARBON、STEEL_INGOT 已完成初步靜態核對，DEC 與 Preview 仍待驗收。CARBON 額外發現煤炭方塊路線，證明單一註冊來源不代表完整配方。
- 釐清 SF5 物品註冊、RecipeType、PostSetup 與動態機器配方的責任分工。**不能只依指南、翻譯檔或固定配方清單推斷完整取得路線。** 後續維持靜態原始碼交叉驗證，動態與隨機配方標記待確認，不建立伺服器執行期匯出器。

## SF5 繁體中文翻譯

- 建立獨立的 `D:\SF5-Translation` 工具流程，使用 OpenCC 與 `@繁簡詞對照` 轉換 SF5 原生簡中。已處理 7 個 YAML、3,043 個文字值，其中 2,563 個發生轉換；結構、雜湊與佔位符檢查通過。
- 完成 BATTERY、CARBON、STEEL_INGOT 三項遊戲內冒煙測試，驗證 YAML → JAR → 遊戲流程。建置期間遇到版本來源 404 與 JDK 下載異常，改用可驗證的來源與 SHA-256 檢查。**編譯成功及少量冒煙測試不代表整份翻譯或 Fork 版本已完成驗證。**
- 建立 **5,154 項** Markdown 翻譯審核清單，分為配方 654 項與其他 4,500 項。採核取方塊控制匯入，「我的譯文」僅填文字，原色碼由工具保留。重新匯出遇到既有審核文件時停止，避免覆蓋人工成果。
- 11/22 完成粗譯審核 V1.1，修正 2,430 項，保留原有勾選與來源識別碼。後續人工審核確立 SF4 舊譯、臺灣用語、玩家習慣及功能優先原則。**SF4 舊譯可作為參考，但可能存在錯字、過時機制或錯誤的跨行語序，不能無條件採用。**
- 確立加壓艙、加熱壓力艙、盔甲鍛造臺、洗礦機、冷凍艙、黑鑽石、人造鑽石等術語。同一設備須跨 YAML 保持一致，避免同一機器因不同翻譯來源產生多個名稱。
- 建立 `slimefun-playful-l10n` Skill，採用 **Playful, not childish** 風格。物品名稱與數值維持正式，說明文字允許適度冷面幽默。三篇巴哈攻略因 HTTP 403 無法讀取，後續不得將未成功取得的文章當作已驗證的文風依據。
- Codex 依完整 YAML 路徑處理 `description`、`usage`、`lore`、`stats`、`type` 與訊息陣列，支援跨檔上下文重組。**具有索引不代表都是可自由改寫的說明文字；翻譯前應先辨識欄位功能，並以整組語意而非單行英文為單位。**
- 11/23 完成三份其他翻譯對照文件批次更新，**新增確認 4,483 項，保留原有 3 項，剩餘 14 項待審**。其中重新翻譯 2,263 筆、多行改寫 347 組、俏皮語氣 11 組。依 Codex 報告，Git Diff、索引、review ID、色碼與佔位符檢查通過，基準文件未修改。
